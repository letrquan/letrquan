## Platform

web

## Users

The profile serves three audiences:

- hiring teams assessing technical range, product judgment, and fit;
- developers evaluating the products and deciding whether to try them;
- potential collaborators and open-source contributors looking for a meaningful place to engage.

## Product Purpose

This GitHub profile introduces letrquan / Zain as a software engineer and product builder. It should establish credibility quickly, make selected work easy to evaluate, and direct visitors to relevant repositories or collaboration paths.

## Positioning

The profile centers on AI product craft: useful developer-oriented tools with sharp, understandable interfaces and reliable foundations. Its work spans provider-agnostic AI agents, browser utilities, and native-feeling desktop experiences.

## Operating Context

Visitors usually arrive from GitHub search, repository links, hiring or collaboration discussions, or product discovery. The primary profile surface is a GitHub README supported by inline SVG assets and repository links.

## Capabilities and Constraints

- Showcase selected repositories with accurate descriptions and direct GitHub links.
- Communicate current areas of work: developer tooling, AI, product craft, browser extensions, terminal experiences, and Windows desktop utilities.
- Preserve factual copy: do not invent customers, benchmarks, testimonials, pricing, adoption, or deployment claims.
- The current implementation is GitHub-flavored Markdown with committed SVG assets, not a standalone runnable web application.

## Brand Commitments

- Profile identity: letrquan / Zain.
- Voice: clear, practical, thoughtful, and technically grounded.
- Emphasize useful software, thoughtful product detail, accessibility, graceful failure modes, testing, and interfaces that remain clear as systems grow.

## Product Principles

1. Demonstrate product judgment through concrete work rather than broad claims.
2. Make technical breadth easy to scan without obscuring the most important projects.
3. Pair AI capability with understandable, trustworthy interfaces and reliable engineering.
4. Preserve accuracy: every project description and proof point must be verifiable from the profile or linked repositories.

## Accessibility & Inclusion

Target WCAG 2.2 AA for authored profile assets and content, including meaningful alternative text, adequate contrast, legible type, and no meaning conveyed by color alone.
